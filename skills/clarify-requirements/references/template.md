# 需求决策稿 / Requirements decision brief

按任务规模删减章节。用实际证据填写；无法验证的内容写成假设或待确认项。
Trim sections to fit the task. Use observed evidence; label anything unverified as an assumption or open decision.

| 要写什么 / Field | 填写提示 / What to capture |
| --- | --- |
| 要解决的问题 / Problem | [谁在什么情况下遇到什么困难？现有做法是什么？] / [Who struggles, when, and how do they handle it today?] |
| 证据与用途 / Evidence and downstream use | [事实、来源、覆盖范围；谁会使用结果、做什么决定？] / [Observation, source, coverage; who uses the result, and for what decision?] |
| 本期建议与范围 / Recommendation and scope | [本期支持哪些用户和场景？先保留什么做法？何时值得扩展？] / [Which users and scenarios are in scope? What existing behavior stays useful? What would justify expansion?] |
| 候选方案 / Options | [复用现状、局部改动或新功能；比较频率、出错代价、用户操作和维护成本] / [Compare reuse, targeted change, or a new capability by frequency, error cost, user effort, and upkeep.] |
| 默认、例外、无法判断 / Default, exception, unresolved case | [每类情况的触发条件、处理动作和可观察结果] / [Trigger, action, and observable outcome for each case.] |
| 待定分歧 / Open decisions | [问题、确认人、答案会改变的规则；能先推进的假设] / [Question, decision owner, affected rule, and any assumption that permits reversible progress.] |
| 验收 / Acceptance | [给定条件 → 执行动作 → 观察结果；至少覆盖主路径和关键例外] / [Given → when → then; cover the main path and the consequential exception.] |
