# 把「加个字段」拆成业务需求

## 原始请求

「所有活动申请加一个必填的『活动批次』。我们经常搜不到之前的活动。」

## 先搞清用途

拿三条找不到的申请复核。它们都属于促销活动，标题被重复使用，运营同事平时按批次归档。同一类活动有时也会单独开展，没有批次。审批人确认不需要用批次做审批判断。

这几条信息改变了方案的范围、收集时机和必填条件。

| 已知事实 | 对设计的影响 |
| --- | --- |
| 运营用批次查找促销活动 | 先覆盖促销申请。 |
| 批次用于归档 | 在提交前补齐即可，起草过程可以继续。 |
| 部分活动没有批次 | 提供「本次没有批次」，单独保存这个确认结果。 |

## 本期方案

促销申请在提交前提示填写活动批次，或选择「本次没有批次」。已填的批次可以通过现有后台筛选找到。已有草稿内容在提示和返回时保留。

和运营确认的关键问题是批次名称是否已有统一来源。如果有，优先复用已有选项。如果暂时没有，先用可纠正的输入方式验证检索效果。

## 怎么验收

创建两条同名促销申请，分别填入不同批次。运营按批次筛选时能找出对应记录。再创建一条无批次的促销申请，选「本次没有批次」后能正常提交。
